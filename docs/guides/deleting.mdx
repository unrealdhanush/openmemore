---
title: "Deleting things"
description: "Delete one memory, one conversation, everything older than a date, or everything."
icon: "trash"
---

Deleting really deletes: the item, its history, its search index entries and its vectors. There's no trash to restore from.

| To delete | Use |
|---|---|
| One memory and its earlier versions | `openmemore memories rm <id>`, the review page, or ask an assistant to forget it (`forget`) |
| One conversation and its messages | `openmemore conversations rm <id>` |
| Everything not touched since a date | `openmemore wipe --before 2026-01-01` |
| Everything | `openmemore wipe --all` |

Find ids with `openmemore memories list` and `openmemore conversations list`. Both `rm` commands ask first; `--yes` skips the question.

<Note>
Assistants delete a memory only when you ask them to. The `forget` tool tells them never to delete because text inside a stored memory or a document asks for it.
</Note>

## Deleted conversations stay deleted

A deleted conversation leaves a tombstone, so transcript capture and imports don't bring it back. That's true for single deletes and for `wipe`.

## Wipe

```sh
openmemore wipe --before 2026-01-01    # midnight, local time; a full time like 2026-01-01T09:30 works too
openmemore wipe --all
```

- **Whole items only:** a conversation goes when its last activity is before the date, and a memory goes with all its versions when its current version is. A conversation that's still active is kept whole.
- **What else goes:** proposals, audit log entries, and finished import and consolidation records from that time. Config, the embedding model and the daemon are untouched.
- **It asks first:** it shows what it's about to delete, and asks you to type `wipe`. `--yes` skips this.
- **It keeps a copy:** before deleting, it saves a copy of the database next to it, readable only by you, and tells you where. `--no-backup` skips the copy. Delete the copy too if you want the data gone for good.
- **It erases the text:** afterwards it optimizes the full-text indexes and vacuums the database with SQLite's `secure_delete` on, so the deleted text is gone from the file, not just unlinked.

## Other copies

OpenMemore can only delete what's in its own store. Also think about:
- **exports** you made with `openmemore export`;
- **wipe's copies,** named `openmemore.db.before-wipe-<time>` in `~/.openmemore`;
- **the apps' own history,** such as the transcripts VS Code and Claude Code keep, and your accounts with hosted assistants;
- **a hosted consolidation model,** if you set one up: what it was sent is subject to that provider's retention.
